## Decision

### Code hosts

Every read and write of a project's repository service goes through one contract, `hide-core/src/code_host.rs`; two hosts are registered (`CodeHosts::STANDARD`), GitHub (`hide-core/src/github/host.rs`, through `gh`) and gitlab.com (`hide-core/src/gitlab/host.rs`, through `glab`: its reads, the head-conditioned merge, the merge proof and a change request by number), and each unit is the only code that knows its CLI, its addresses and its failures.
A host is one registration unit (`CodeHost`): the base contract every host has, and each optional operation as an accessor that answers `None` when the host does not offer it, so an operation a host did not declare cannot be called and its caller refuses the request rather than reading the absence as an empty answer.
The base contract is how the host names a repository and reads a remote's address, the addresses it makes (repository, change request and its checks and files pages, commit) and how it writes a change request's number, whether it finds a checkout's remote itself, its read of a project (`HostReads`) and a change request's card.
The optional operations are the head-conditioned merge, the branch update, the body's closing line, the merge proof, the base branch's push rule, the exact-commit checks, a failed check's log, a change request by number, the agent handover, issues, search and the cheap watch.
A repository is a `RepositoryRef` (`host`, `authority`, `path`): the host's key, its server with a port when the address names one, and its path there; only its host's unit makes one, and its stored name (`OWNER/NAME` on github.com, `HOST/OWNER/NAME` on a GitHub Enterprise server) is the unit's inverse of it, so stored settings and wire fields keep the names they had.
Common code receives a `Place` (a repository by name, or a checkout its host resolves itself), a `HostFailure` whose category the screen words, and on each pull request the `ChangeRequestRef` its unit made when it read it (repository, number, key, label, and its own, checks and files pages); it never branches on a host's key, spells a host's command or address, or reads an address again to find a repository.
A reference's `key` is the name every reference to that change request shares, folded the way its host folds names (`CodeHost::repository_key`; GitHub lowercases the path and keeps the server and port), so the core and the screen compare references by equality alone.
The wire carries the reference beside every pull request address the screen opens or compares: each pull request, a session's pull requests (agent marks, the session record, PR groups), an archived member's pull requests, the link record's pull request rows, and as `pr_reference` beside `pr_url` on a mission node, a memory promotion and a suggestion row; a mission node names every number it holds by one, made by the unit of the host of the repository the project's read named when the list holds none (its pull requests, `pr_reference`, `base_reference` beside `base_pr` and `outside.reference` beside the number a waiting node waits on or whose CI it waits on, and the phone's `base_reference` and `external_reference`), each absent from an older core and read as `#n`; an address Hide holds without one (a session's record, a saved node or promotion) is named by the unit of the host it is on (`CodeHosts::reference_at`), and the identity carries its repository's page (`url`, absent while its server is not known).
A saved answer's references are made again on restore by the unit of the host each names, from the repository and number it saved, so a file saved before the unit made a field reads like a fresh answer; one of a host no unit is registered for keeps what it saved, and is dropped if it was saved before keys were made.
The registry (`CodeHosts`) picks a project's host and is the only place that does: an explicit repository setting or a device's `origin` is read by its name; a checkout whose remotes name no repository a registered host reads is answered "no remote" with no host asked; remotes of one host go to that host, in the checkout when it resolves checkouts and by the first remote's name otherwise; remotes the node did not name, or remotes of several hosts, go to the first host that resolves a checkout itself (GitHub's `gh`, which picks one in the checkout); a server a registered host names is that host's, and any other server a host reads (a GitHub Enterprise one) is the first such host's.
A checkout's remotes reach the core as the addresses its node read (`PathFacts::remote_addresses`), and each registered unit reads them (`CodeHosts::remote`); from an older node that sends only stored names, those are read instead, and an older node that names none has its remotes not known (`Placement::RemotesNotKnown`): the reader answers it as no remote on the wire with no host asked, keeps it apart in the core (`remotes_not_known`) and logs it once per checkout, since GitHub-shaped names say nothing of another host's remote.
A remote address leaves a node without the user part of a `scheme://` address (`hide_node_link::catalog::without_credentials`, applied to the catalog's addresses and a checkout's origin), and the core applies the same function where an address from a node enters it, because an older node sends it raw; a gitlab.com unit handed an `https` address that still carries a user part reads no repository from it.
An explicit repository setting is accepted only as a registered unit's own stored name of a repository on a server its host names, so with GitHub alone it stays `OWNER/NAME`.
One common reader (`code_host::read::CodeHostReader`) decides which projects are due, answers the ones no host reads, hands each host the projects that are its own and keeps every answer; what a host keeps between passes (its sign-in for a pass, the checks it carries) is its own.
The projects read are capped by one total, the largest registered limit, taken over every project in rank order, a project no host reads included, and inside it by each host's own limit (`CodeHosts::within_limits`).
A read names the repository's identity (`RepositoryIdentity`: the reference, the host's name of it, the host's id, its visibility and default branch) apart from its issues, so a failed issue read keeps it, and the link record and a mission's admission key on it.
GitHub's read asks `gh` the same commands main did, its identity included (`repo view` with `nameWithOwner,id,visibility,defaultBranchRef`), and a test holds a pass's argument lists equal to the ones main's own pass asked, in a checkout and by name.
A place that names its repository carries its server; for a checkout `gh` read in place, GitHub's unit alone decides the server from data the common code passes it (the repositories the registry read from the checkout's remotes, `Place::Checkout`), the first step that answers deciding: this pass's pull request and issue addresses of the repository name one server; `auth status`, which the pass already asks, names exactly one server, the only one `gh` can have answered from; every remote's host is claimed and they name one server, whatever its path (a renamed repository's remote keeps its old path); the remotes whose path is the repository's name name one server, and it is claimed.
A remote's host is claimed when it is `github.com` or a server `auth status` names, and unconfirmed otherwise (an SSH alias, a server `gh` is not signed in to, any server but `github.com` when the answer is empty or unreadable, as a `gh` before 2.72 prints it to stderr).
The two steps that read the remotes answer only from a complete list (`Place::Checkout::remotes_complete`): a remote no registered unit reads, or remotes the node did not list, leave it incomplete, since a remote nobody read could be on any server.
When none settles it, or the addresses disagree, the identity's server is not known (`RepositoryIdentity::repository` is `None`): the read is still read, `gh`'s name, id, visibility and default branch stand, nothing that needs the server is made from it (no address, and no key another server's repository could match: the link record and a mission's admission take neither its bare name nor its id), a pull request listed in the pass keeps the address `gh` gave it, `repository.server_unknown` is logged once per repository, and a later pass that reaches one of the steps settles it.
An identity read that fails is its own outcome (`GithubProjectSnapshot::identity_read`), logged as `repository.identity_unread` and retried like failed issues; the identity read before is kept only where nothing says the pass reads another repository: on a pass that read its list, when a pull request reference it read or the repository its place names is that exact repository (host, server with port, path), and on a pass whose read failed, unless its place names another repository or host; a project answered "no remote" keeps none (`keep_previous_reads`).
Matching remotes alone are no such evidence, since `gh repo set-default` and a moved origin beside an unchanged upstream change the repository the same remotes read.
Each part of a read (today the issues) is one of four outcomes (`PartRead`): unsupported by the host, not read, failed, or read (and maybe empty); only a part the host offers and did not read holds the project's re-read clock back.
`code_host/tests.rs` registers a host with the base contract alone in the test binary and holds it and GitHub's unit to the same contract tests: the choice of host, the four outcomes, an undeclared operation's refusal, addresses and number labels.
`scripts/check-code-host-seam.py`, a `verify` gate, refuses starting a host's program, a host's failure or place type, a host's address and a host's key in any form in Rust (`hide-core`, `hided` and `hide-session`, whose hosts' session halves live in `hide-session/src/hosts/`) or TypeScript outside the files it names as a host's implementation (test code is not read).
A host's program is started by one of three doors, each refused outside the unit: constructing its node call, naming the program, or using the node link's module for it beyond the items that start nothing; a list of argument words that reaches no door is not refused, because no operation of a unit takes argument words from common code; the web files that still read GitHub addresses themselves are named there as known exceptions until the screen opens the references the core carries.
