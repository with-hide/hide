# 0006. Resident process ownership

- Status: Accepted
- Date: 2026-10-04
- Code: `desktop/src/main/spawn.ts`, `desktop/src/main/host.ts`, `hided/src/supervisor.rs`, `hide-node/src/terminal/holder.rs`, `hide-node/src/ssh/host.rs`, `hide-host/src/serve.rs`

## Decision

### Resident process ownership

The process that starts a resource and the lifetime owner are not always the same: the desktop host deliberately starts session services that outlive its window.
That product lifetime is the local exception to treating host quit as the end of every child; it does not exempt the service's own workers from engineering principle #14's cleanup rule or #15's caps.
The following table describes Hide's current macOS startup path, not an operator's separate service configuration or a promise of restored live processes.

| Process | Starter and lifetime owner | Stop condition | App quit | Reboot and login |
| --- | --- | --- | --- | --- |
| Desktop host computer-use reader | The Electron main host owns `ComputerUse` and its one timer and four powerMonitor subscriptions. | Host quit clears the timer and removes every subscription. A closed shell connection releases its activity and Needs You demand in hided. | Ends with the host; hided continues with no activity from that host. | Gone; the next host starts a fresh reader and replays its current value when its shell connects. |

The local executable authorities are `desktop/src/main/{host,spawn}.ts`, `hided/src/{cli,env,lib,server}.rs`, `hide-node/src/ssh/host.rs` and `hide-host/src/serve.rs` with `hided/src/node_cli.rs`.
Which of these a `hided` process is comes from its arguments, read once before anything else runs (`hided/src/role.rs`): no argument at all is the daemon, `core-login`, alone or with an absolute `--state-dir`, is the daemon as a login item starts it (a moved core's or a paired machine's), each other role in the table takes its own words and refuses the ones it does not know, `--version` and `--help` print and end without reading the environment, and any other argument is refused with exit 2 before an owner watch, a state folder, a lock or a log is touched, so a stray argument on a device can never start a second core there (`hided/tests/it/arguments.rs`).
One `hided` process runs one role at a time and may run two in its life (`hided/src/supervisor.rs`): a core that the import of an earlier engine's save starts again, and a node that becomes its machine's own core once it is split from the core it dialed ([Splitting a moved core's two machines](0040-splitting-a-moved-core.md#splitting-a-moved-cores-two-machines)).
A role's end and the process's stop request are each level-triggered (`hided/src/ending.rs`), because the process outlives its roles: a `Notify` dropped what no task was waiting for, so a stop that came while the supervisor was busy was lost and the old role's listeners and their core outlived the role.
The signal handlers are installed once, before the first role runs, every wait of the supervisor selects on the stop, and `hided` waits at most a second at its exit for blocking work a stop left behind.
The role that ends closes each of its sockets with 1012 (`role_ended`, through `AppState::role_ended`), so a window reconnects to the role mounted next on the same seat, address and token.
A core is stopped or counted as running only by a pid its state proves by the start the kernel reports for it now (`DaemonState::is_proven_running`), so a pid another process took since is never signalled; a state that proves nothing leaves the instance lock to decide.
The one-release kit retirement stage is `hide-kit/src/coordination_retirement.rs`; it does not start a resident service.
It reads legacy v1 and current Hide-only v2 Sasu registries without importing them, checks their retained run states, and refuses if the authoritative revision disappears after selection.
After reboot, hided and its watches start with the app; no login automatic start is added.
An app exit preserves service ownership, but a reboot ends the prior daemon, pane holders and helper processes; persisted layout/session references are not continued execution or proof that an agent completed its task.
hided's replacement checks the named daemon's health and process identity before signalling it, and leaves pane processes alone (`cli.rs::connect`, `cli.rs::stop_daemon`).
The device helper admits 4 running requests and 32 queued requests on the core connection; revocation's drain bound is 250 s, while each call has its own deadline (`hide-node/src/ssh/host.rs`, `hide-host/src/serve.rs`).
A device has one connection, the `ssh` child whose standard streams are the node's link, and the device's engine, files, Git, terminals and pages are that link's calls and streams; its pane service holds at most sixteen callers and eight streams, and at most four devices dial at once (`MAX_DIALING`, `hide-node/src/ssh/device.rs`).
Desktop CLI children, attach streams, provider children and bridge helpers have narrower owners than these session services; their cleanup and budget belong to their existing feature sections and the [resident work ledger](../PERFORMANCE_TESTING.md#resident-ticks-timers-and-watchers).
