# 0026. Session threads

- Status: Accepted
- Date: 2026-10-31
- Code: `hide-core/src/runtime/session_thread.rs`, `hide-core/src/input_queue.rs`, `hide-core/src/runtime/input_queue.rs`, `hide-core/src/operator_input.rs`

## Decision

### Session threads

A session thread (PRD session-docs-and-assistant B25-B29) is one agent pane's session drawn as a conversation, and its input box types into that pane.
`hide-core/src/runtime/session_thread.rs` owns it: one thread is open at a time, as one session record is, opened by `session_thread_open {pane_id}` and closed by `session_thread_close`.
The pane's session is the one the engine reports for its agent, kept on its delivery observation for every agent with a thread reader, OpenCode's database included (`ThreadReference`); a pane whose agent reported none, or whose runtime has no reader, opens as `failed` with `no_record`, and a session it reports later in the same terminal is read then; a reported session whose file is not there yet, or for Claude Code holds no message yet (`session_file_missing`, which `hide_session::confirm_session_file` answers for a Claude file read whole with no person's or assistant's record), in a pane that still runs it is `ready` and empty while it awaits its first record, read again each second in place of the look until a page or a refusal answers, a refusal then showing as `refused` or `no_record`, whereas a thread that read and drew a page keeps it past a refusal; both rules read one fact of the open thread, whether a page arrived (`drew_page`), which a busy or lost node or a record not written yet never sets; only a gone pane's missing file is `no_record` (`ReadFailure::NotWritten`, `hide-core/src/runtime/session_thread.rs`).
The record is read where the session runs, by that machine's node (`Call::SessionThread`, protocol 66, the `thread` reader feature), on a worker outside the lock, and the answer comes back under a short lock with the open thread's generation, so an answer for a thread that closed is dropped.
The newest page is read once and kept; what the session writes after it is read forward from where that page ended (`ThreadRead::From`), again when an engine read shows the agent's state or state sequence moved and, while a renderer is attached, whenever a once-a-second look (`Call::SessionActivity`) says the session's file moved, in every agent state while the thread is drawn for its pane; with no renderer attached the thread rests, and a renderer attaching after none was takes one look at once.
Each panel showing the thread holds it from its window (`hided/src/demand.rs`, `ThreadHolds`): the core hears a close only when the last hold is let go, or when the last window holding it leaves without a close (a reload, a crash, a lost socket); another pane's open replaces the thread and the holds on it, and a tool's connection (no `client_kind` of a window) holds none. A panel says its open again each time its page's connection is live, because a reconnect is a new connection that holds nothing.
The state change alone reads too early: an agent writes the end of its turn after it reports the turn ended (Claude Code appends its last answer once its Stop hook ran, 70 to 100 ms later), so a look that waited for `working` missed every answer until the next prompt; the file, not a sampled state, says the end is there.
A look runs on its own worker thread outside the lock and on a call thread of the session's node, and only its time and size come back.
The first look of a session locates its transcript and proves its owner from the file's header records: one stat for Claude Code with a cwd, a listing of up to seven day folders of rollouts for Codex by id, a listing of the checkout's session folder with a header read of each file until the id is found for Pi, omp and Grok without an id, and a database open, proof and aggregate query for OpenCode.
The node remembers where a plain look found the session (`hide_session::session_activity`, at most 64 sessions, the one used longest ago dropped): a later look whose file kept its identity, size and time answers from there with no proof, and one whose file moved proves that file alone before the session is located anew.
A failed look takes a read's path: a node that is not linked or not connected dims the thread and a read asks again 5 s later, a busy one is looked at again after 500 ms, and any other failure, a look that got no answer in time included, is logged once per reason (`session_thread.look_failed`) and looked at again 5 s later with the thread still lit; the 5 s `ACTIVITY_TIMEOUT` bounds the caller's wait, not the node's file work, which keeps its call's place until it ends.
One live read is out at a time, with one more owed when the record moves during it; a forward read that fills past 512 KiB becomes a kept page and the next starts where it ended, and the thread keeps four whole pages, an older one read on request (`session_thread_older`) refused past them as `capacity`.
A node that cannot be asked leaves the thread as it was with `connected` false and is asked again 5 s later; a busy file is asked again after 500 ms; a cursor whose file was replaced starts the thread over from the newest page; a refusal after the thread drew keeps what it drew and goes to the diagnostic log.
Two snapshot sections carry it, each on its own revision and replaced whole: `session_thread`, the state, the pane check, the live page and the input's state, and `session_thread_history`, the kept pages, which change only when a page is read or the live page fills, so a working session re-sends its live page only.
Each page carries the ACP updates as `hide-session` wrote them and its `parts`: a shell call whose command is a `hide` command that makes a Hide part (`hide task set|node|approve|drop`, `hide agent spawn`, `hide request send`, `hide browser|file|diff open`, `hide mission ...`) is named by what it made, by its tool call id (`hide_session::thread::hide_call`), and a spawn takes its agent id from the call's output when that arrives, on the same page or a later one (B26); the screen looks each part up in Hide's own state by those names.
A page's `sessions` places each session a letter, a spawn or a received letter's sender names (a registration id or name, as written) at the pane and machine of the live registration that answers to it, as a letter's target is found (`coordination::registered_record`), so a chip draws that session's row; an ended or unknown name is left out and its chip draws the name alone.
The read's worker turns the answer into the page the snapshot holds (its JSON updates, parts and sessions) before it takes the lock, from the ledger and the earlier pages' parts it was handed when the read started.

The input box's words reach the pane through the one operator write a phone's reply and keys take too (`hide-core/src/operator_input.rs`): the screen stages its files as a terminal attachment's (`attachment_stage`) and sends `thread_input`; hided commits the stages and sends the core `session_thread_input`, an event only hided makes.
The core sends only to the pane the thread was opened for while that pane still runs the session it was opened for: the same pane, terminal and session reference, else `pane_changed` or `pane_gone`, and one input at a time.
An input for a thread that closed, or for a pane whose thread another window replaced, types nothing and is answered `closed` by its request id on the requesting connection, so the screen that sent it gets its words back.
Each input, model or effort change, and thread interrupt completes directly to its requesting connection as `thread_input_result {request_id, state, reason}`, through a nonblocking completion owned by its existing worker, so display snapshots coalescing another window's refusal and a sent input cannot erase either answer.
Admission to the waiting line completes as `queued`, which clears the accepted words and files from the box just as `sent` does; a refusal keeps them.
The socket loop holds one completion receiver, refuses another request as `in_flight`, and releases the receiver when the connection ends; it adds no reader or waiting task.
A completion lost before it reaches the socket closes that connection; the window restores unanswered words, marks delivery uncertain and requires a visit to that pane's terminal before another send, with no automatic resend.
The snapshot's `input` remains display state only.
Its words pass the one rule every operator input passes (`operator_input::problem`): not empty, at most 16 KiB (`operator_input::LIMIT_BYTES`), and no control character but a new line and a tab, which stay inside the engine's bracketed paste and submit nothing.
A worker stages a device pane's files on that device (`terminal_attachments::read_sources`, `stage`), puts their quoted paths before the words as a terminal attachment pastes them, and hands them to `operator_input::write`, which waits on the pane node's input permit and the sleep gate, asks back once more, last (here the runtime lock, to check that the thread is still open on the same pane and session), and outside the lock sends the words through the engine's `prompt_agent`, typed as a letter's bell and a phone's reply are, not as keys typed into the terminal ([UI_BEHAVIOR.md](../UI_BEHAVIOR.md)).
The write names its outcome the same way for every surface (`operator_input::Unwritten`): an engine refusal typed nothing (`input_refused`, `pane_gone`), an engine that could not be reached typed nothing (`unavailable`), and only an engine that never answered leaves it in doubt (`uncertain`).
The send marks a key before it and a key and a submit after it (`note_delivery_reply`), so the doorbell neither types over the words nor takes them for a draft, and reads the thread on.
A screen that reaches its core through a node's daemon stages its files on that node, which a thread's input does not hand on: its files are refused as `unknown_stage` and its words go through.

#### A session's model and effort

A session's input box changes the running session's model and effort the way its agent does in its terminal: the line its definition's `[switch]` names, typed into the pane (mission-106).
The screen sends `session_thread_switch {generation, pane_id, request_id, model | effort}`, one of the two; the core finds the agent of the thread's pane from its delivery observation (`definition::find`, as the box's answers do), builds the line with `hide_agent_adapter::definition::Switch::line` and types it through the thread's input path (`type_into_thread`, the same operator write, permit and checks as the box's words), answered by the request id on the requesting connection as an input is.
The line ends with Enter, which answers whatever the agent shows, so it is no operator's words: the core refuses it while its observation of the pane reads a question (`blocked`, `agent_asking`), a turn (`working`, `agent_busy`) or words never sent (`Observation::unsent_draft`, `draft`), the readings the doorbell holds a letter on, and types it as `operator_input::Typed::AtRest`, which the engine takes as `PromptBy::Letter`, refusing a pane that moved to a question or out of its input after that read; a refused line notes no key, so it leaves no draft behind.
A value the line could not carry as one word (`hide_agent_adapter::valid_model`, an effort the definition does not list) is refused before anything is typed, as is a slot the agent has no line for (`switch_unsupported`) and an effort line that names the model while the session's model is the CLI's own (`needs_model`).
Once typed, the session's choice is what the line made it (`Switch::after`; Codex's model line puts the effort back to the model's own): it goes on the pane's launch record when that record describes the agent (`keep_launch_choice`, `ui_state.pane_launches`), so a wake, fork, reopen or resume starts it with that choice, and otherwise into a map by the session the agent reports, at most 256 sessions, kept while hided runs; past that the session changed longest ago is let go and shows its start's choice again.
The thread section's `choice` is that value, read when the thread opens and after each change; a change the operator types in the terminal is not seen.
The lines, each checked in the agent's own terminal on 2026-11-26: Claude Code 2.1.332 `/model <m>` and `/effort <e>`, which it also keeps as its default for new sessions; Codex 0.172.0 `/model <m>` and `/model --reasoning=<e>`, for that session only; Grok 1.0.92 `/model <m>` and `/model <m> <e>`; Pi 1.0.4 `/model <provider/model>` and `/thinking <e>`; omp 18.7.0 `/effort <e>`, its `/model` taking no word; agy 1.5.18 `/model <m>` and `/effort <e>`; OpenCode 2.0.29 has none, its `/models` and `/effort` opening dialogs that take no word.
The web contract carries each agent's lines and efforts (`switch` in `contracts/agent-adapters.json`), which the bar reads to offer a slot or show it read-only.

#### The operator's waiting line

Words the operator sends to an agent that works wait in the core and go one at each rest (PRD desk-queue), so Enter never answers what the agent shows mid-turn and every agent takes them the same way.
`hide-core/src/input_queue.rs` owns the line as data and its file, and `hide-core/src/runtime/input_queue.rs` owns what the runtime does with it; the core holds one line per pane, keyed by the pane id the core names, so a device's pane has its own.
The session input (`type_into_thread`) and a phone's reply (`hided/src/mobile/phone.rs`, which asks `Core::input_waits` first) route through `Runtime::input_route`: a pane whose agent works, whose line holds words that are not paused, or whose last line has not shown its turn yet takes the words into the line (`queue_input`), answered `queued` on the thread's input; an agent at rest or asking, with nothing waiting ahead, is typed at once as before (D-23).
A line keeps its words, the paths of its files in hided's folder for waiting input (`hide_kit::layout::input_attachments`, which hided's sweep never empties of a file a line or Desk still names: `Core::input_files_in_use`), their size and the id a device stages them under.
The caps are counted when a line comes in and when `input_queue_restore` puts cleared lines back: eight lines (`LINES_MAX`, Desk's `DESK_QUEUED_MAX`), one send's 8 files and 40 MiB across a pane's waiting lines, and every pane's lines at most `SAVED_BYTES_MAX` (3 MiB, counted as the encoded file, below the 4 MiB the file is read back with, so a file the caps allowed always reads back whole), refused as `queue_full` and `queue_files_full`, the words staying in the box; nothing in the line is dropped for room, since every line is unfinished work, and a refused restore keeps the cleared lines and says why on the snapshot (`cleared.refused`).

The doorbell's pass sends the lines (`Runtime::send_queued_lines`) before it rings a letter, on the same verdict a letter waits for (`doorbell::judge_operator`): no question on screen, the turn ended, the record read, no draft in the agent's prompt; it skips the bell-target kind check, the mid-turn wait and the 30-second quiet, which belong to letters.
While a pane's line waits and the operator's verdict there is a rest (`Runtime::input_queue_holds_bell`), a letter's verdict and a bell reserved for it are `Hold::Queued` (`operator_line_first`), so the operator's words go first and the letter rings at the rest after the turn they opened; a bell the doorbell lets into a working turn (five minutes, `--now`) rings as before (D-13).
A line goes through `operator_input::write` as `Typed::AtRest` (`PromptBy::Letter`): a pane that moved to work or a question after the verdict is refused by the engine, and the line stays first for the next rest, retried after 2 s (`RETRY_MS`); one line is typed at a time, and the next waits until the agent's state sequence moves past the one the last was typed at (`Queues::follow_typed`); a line that opened no turn leaves the sequence still, and once a doorbell observation taken at least two passes after the typed one (the pass in flight may have read the pane before the words) judges the pane at rest, the line reads `stalled` and `input_queue_resume` lets the next go, so the normal path never shows ▶ and no timer guesses a turn.
Before a line is typed its `sending` mark is saved and the worker waits for that write (`LatestFile::save_written`, up to 10 s, off the lock); a save that fails types nothing and the line waits for the next rest, and a file read back with a line still marked `sending` restores it paused and `uncertain`, since the engine may have taken it before hided stopped.
An engine that never answered leaves the line `uncertain`, and a device's file that could not be staged, a file that is gone or a refusal leave `device_unreachable`, `file_missing` or `refused`: each pauses the line with the reason on the line, and nothing is typed again until the operator sends it (D-14).
The pane's agent kind and its turn are followed on each pass (`Queues::follow`): no agent, another kind (`hide_agent_adapter::canonical_kind`), or a turn the agent reports the operator stopped (the hook's idle turn, else the session record's interrupted turn: `TurnProjection::interrupted`) pauses the line; after a restart a pane's line is paused for a missing agent only once its agent was seen this run.
A pane the core no longer holds lets its line go (`retain_terminal_pane_state`); a pane with a waiting line is never put to sleep (`agent_sleep::Awake::queued`).

The moves are events: `input_queue_remove`, `input_queue_send` (a paused line, while the agent rests), `input_queue_resume`, `input_queue_clear` (kept 10 s for `input_queue_restore`, which puts the lines back first, paused) and `session_thread_interrupt`.
■ checks that the agent works, reads the keys of its definition's `[interrupt]`, holds the line (no line goes while the keys are on their way) and types them as `Typed::Interrupt` through the same write on a worker, answering on the thread's input; the engine's `interrupt_agent` is the last check and types only while its agent is Working, refusing `agent_blocked` or `agent_not_working`, so an agent that asks or ended by then gets nothing typed, `agent_asking` on the input, and its line is not paused; the line pauses only when the keys landed or may have (D-24).
The phone takes the same three steps through `Core::interrupt` (`InterruptStep::Start`, `Ready` right before its write, `Answered`).
The open thread's section carries the pane's line (`SessionThreadSnapshot::queue`: `waiting` or `paused`, the lines with their files' names, `sending` and `failure`, the cap and what a clear kept); the phone reads it through `Core::input_queue` ([The mobile companion](0059-mobile-companion.md#the-mobile-companion)).
The diagnostic log names each move by pane and line id (`input_queue.queued`, `.refused`, `.held`, `.typing`, `.sent`, `.paused`, `.interrupt`) and never the words or the files' names.
The line is saved off the lock to `input-queue.json` (`hide_kit::layout::input_queue`, its state folder conversion keyed by pane), a line on its way kept with its `sending` mark, so a restart of hided keeps the lines, their state and their files.
Desk keeps its own line in `desk.json` ([Desk's commands](0032-desk.md#desks-commands)) with the same pause (`queued_paused`, set by `desk_stop`), `desk_queued_send`, `desk_queued_resume`, `desk_queued_clear` and `desk_queued_restore`.
