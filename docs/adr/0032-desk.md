## Decision

### Desk

Desk (PRD Desk 1차) is a room where the operator talks to an agent they choose, one of the agents switched on in Settings › Agents, over ACP, and that agent starts and follows real sessions through the `hide` CLI.
Three parts hold it, each with one job.

- `hide-desk` is the ACP boundary and keeps no state: the ndjson JSON-RPC connection (`rpc.rs`, a line capped at 8 MiB and 16 calls waiting), the session in each adapter's own mode (`session.rs`), each catalog agent's ACP route and pin (`adapter.rs`, which lists the agents of `hide-agent-adapter`'s catalog that start in a pane, and `contracts/desk-adapters/` for the npm adapters), the npm adapters' install (`install.rs`), the process (`host.rs`) and how a request is read into a card and whether it is a `hide` line (`permission.rs`).
- The core owns the room: the conversation, the choices, the approval cards and the one Desk process (`hide-core/src/runtime/desk.rs`, its worker in `desk/worker.rs`), its store `~/.hide/state/desk/desk.json` written off the lock (`hide-core/src/desk.rs`); agent command lists have their own owner (`hide-core/src/agent_commands.rs`), and the `desk`, `desk_live`, `desk_jobs` and `desk_mentions` snapshot sections.
  Settings › Labs › Desk's switch (`settings.enabled`, off by default and in a store written before it existed, D-76) is kept there too: while it is off the worker looks at no agent, every `desk_*` event but `desk_settings_set` is refused as `desk_off`, and so no process starts; turning it off ends the process as `다시 시작` does, and turning it on looks at every agent again and downloads every npm adapter not in place at once (D-80), so choosing an agent never waits on a download.
  Each download is an `npm ci` on a thread of its own, started tied to hided (`run_to_end_tied`), so it ends with hided however hided ends; turning Desk off stops every download under way (`Order::Off`), and a stopped or failed one removes its staging folder before it reports, so nothing writes into `~/.hide/desk-adapters` once Desk is off.
  The agent list is the catalog's agents the kit has switched on for this machine (D-79), plus a chosen one since switched off, shown `off` and not sent to; each carries the sign-in Hide AI's provider row for it reads (D-81): `needs_login` is signed out, `ready` or `usage_limited` with its login checked is signed in, anything else unread, the same rows Settings › Agents words, and an adapter in place never reads as signed in; an agent that refused Desk for its sign-in reads signed out until its next session opens.
  The list is composed again when the kit's agents or those rows change (`desk_catalog_moved`), and Desk asks Hide AI to read the catalog when it is turned on.
  Desk's queue keeps its waiting spawns while it is off and starts none (`desk_start_next`), and turning it on starts them in order; the shell tells the desktop host the switch (`hide:desk`), whose app menu carries `desk_terminal` only while it is on, and the shell's own `openDesk` and `deskTerminal` refuse while it is off, whichever menu or chord asks.
- Desk's lane in the store is two widths, Desk's desk's and the session panel's, under `panel_widths` (`view_width`, `session_width`, PRD desk-2-ui B22, B23), each `null` until the operator drags it; which session is open beside Desk, and whether the desk is drawn, wide or beside its Explorer, are the window's (B26, PRD desk-own-desk D-05).
  A drag let go is one `desk_lane` event naming the width it moved, in whole CSS pixels; zero or past 8192 is refused `desk_lane_width_invalid`, a width read from the file outside that range reads as unset, and the event moves the `desk` section only.
  The lane also keeps whether 한눈에 is folded (`glance_folded`, written only while true), its open tab (`glance_tab`, `sessions` or `files`, written only for `files`) and which of its session groups are folded (`glance_groups {turn, working, ended}`, 끝남 folded at first, written only once it differs from that), each set by the same event (`glance_folded`, `glance_tab`, `glance_group {group, folded}`), so they are the same in every window and after a restart; each of those fields is read on its own, so one a later Hide wrote in another shape is its default and one `desk_store.lane_field_unreadable` line, and an event naming none of them and no width is refused the same way.
- 한눈에, the panel at Desk's right while no session is open beside it (`hide-core/src/runtime/desk/glance.rs`), lists sessions the store keeps under `glance`: by pane, the time Desk started it or the operator last opened it beside Desk, oldest first, the newest 32 (`MAX_GLANCE_SESSIONS`), each entry read on its own so one a later Hide wrote goes alone and an older Hide reads past the key.
  A session Desk started is put forward once, when `refresh_desk_jobs` first finds its pane, at its spawn's reservation time (its `JobMark::glanced` says so after), so one pushed out later is never put back and an unchanged refresh saves nothing; a session is kept at the moment its thread opens beside Desk (`open_session_thread`), only while its pane has a row (this machine's or a connected device's), so a session read from its record alone takes no place; one older than every entry of a full list is not taken and moves nothing.
  A new session kept in a full list first takes the place of the oldest one that has ended (its card's place not queued or starting and its agent not at work or asking, or no longer listed: its tab closed and no job of Desk's), and only with none ended does the oldest go (engineering principle 15); each one that goes is one diagnostic line (`desk_store.glance_ended_dropped`, `desk_store.glance_oldest_dropped`).
  `desk_jobs.glance` carries the listed panes that have a card (each a job's, a worker's, or a named one, since `desk_named` gives every 한눈에 session its row's card) and the files: no list of their own, but read on every build of the cards from the open Views, a session's by its openers as its `뷰 N` list reads them and Desk's agent's by the opener its `hide file open` records on the View it lands in (the core's node and `hide:desk`, which no engine terminal is), with each View's own seen record; those not looked at first, then the newest, at most 32 with the rest counted (`files_more`).
  A `desk_view_open` `output` naming a View of Desk's own desk brings that tab in front where it is and marks it seen, and the tab in front of Desk's desk is seen while the window holding the keyboard draws that desk: the shell's one `window_focus` report names the screen (`workspace` or `desk`), the daemon hands the core the screen of the window that took the keyboard last, and `looked_at_view` (`runtime/unseen_views.rs`) reads that one screen, so the core alone decides what the operator looked at.
  Desk's agent's `hide file open` is placed from the material its host read, through the tab a pane's open takes (`read_file_tab`, which keeps a tab holding the operator's edit), so the View it lands in is known in the same event and stamped with Desk's opener (`stamp_view_opener`, `mark_view_unseen`); that opener is no pane, so a View's snapshot leaves it out and its tab names no opener.
- Desk's own desk is the core's (`hide-core/src/runtime/desk/views.rs`, PRD desk-own-desk D-01-D-04, D-10-D-13): the same View areas a Workspace's Agent tab keeps, with the same operations, kept in Desk's store under `views` and reached by the runtime's View code under its own key, the core's node and `hide:desk` (`Runtime::desk_key`), whose place is `Place::Desk`.
  The key's device is the core's node because the desktop host names a page's partition by device and refuses an empty one.
  A page Desk opened itself loads on that node; a session's page opened on the desk names the session's checkout (`Display::origin`) and loads through that checkout's machine, as it does on the session's own Workspace: `browser_route_source` resolves the page to the origin's registered checkout (none when it is no longer registered), and its `device_id` is the machine hided routes the page through (`hided/src/browser_routes.rs`, `hided/src/node_pages.rs`), which is the View's own machine for every work tab; hided's route, browser-action and relay checks take `hide:desk` where they take a checkout's absolute path (`is_page_checkout`).
  A `view_layout`, `browser_open` or `browser_state` naming that key acts on the desk, and the snapshot carries it as the rest section `desk_view {device_id, path, layout, opened}`, where `opened` moves when an open asks the window to show the desk.
  A press in Desk's room opens there with one `desk_view_open` event: `file {workspace_id, checkout_id, path, device_id?, preview, beside}` opens a registered checkout's file as the Workspace's file view does, `card {card}` one of Hide's cards, and `output {device_id, checkout, id, request_id?}` the same file, address or card as a View a session opened, which that View then reads as seen where it is, only once the desk really shows it: an open the desk refuses (no room, see below) or an outside file leaves the View to look at (`desk_output_gone` when it is no longer there, `desk_output_external` for an outside file, whose grant only its own Workspace's tab stands on).
  An `output` that names itself (`request_id`) gets the receipt a `browser_open` gets in `status.browser_opens`, naming the display of Desk's desk it placed in front, or that it was refused, so the window's keyboard follows a page or a file whose display id it cannot know ahead; a file still being read holds the id on its placement (`ViewPlacement::receipt`), and the receipt is written when the read lands and the file is placed (`desk_open_output`, `hide-core/src/runtime/desk/views.rs`).
  A file on the desk names its checkout (`Display::origin`) and is that checkout's own document, read, edited and saved as the Workspace's file view does (`file_save` by the tab id); the core holds the document while the desk shows it, no Workspace View takes it in for that (`reconcile_view_displays`), and a file it cannot read is an unavailable tab with Retry, as a View's is.
  The desk keeps at most `MAX_VIEW_DISPLAYS` tabs, as a Workspace's desk does; a stored tree is settled as a Workspace's is (`settle_desk_views`): a View the desk never holds (an outside file, a diff, a run's summary, a file with no checkout) goes, past the cap the ones looked at longest ago go, and a tree this build cannot read is an empty desk with the rest of the store kept (B29).
  Desk switched off lets every document of its desk go, unless a Workspace's View shows it or it holds unsaved work, which its checkout then takes in as any document no View shows; the tree stays, and switching Desk on reads the documents back.
  Desk's Explorer lists its session's checkout with the Workspace Explorer's own tree, listing and expanded folders (PRD desk-2-ui B35), and its create, rename, move, copy, import and trash events carry `desk: true`: the core then plans the change against the registered checkout at the event's `root` on its device instead of the checkout in front, a waiting one is not dropped when the front moves, and the core opens no file it creates, since the window opens it on the desk with `desk_view_open`.
  Desk 1차 kept a pin and up to sixteen kept tabs under `lane`: this build does not read that key and the next save leaves it out, and an older build reads past `views`, so an upgrade or a downgrade keeps the conversation and queue.
- Desk's queue starts its waiting spawns one at a time, in order, since this machine starts one session at a time (`SPAWN` in `hide-core/src/coordination/executor.rs`): while one starts, the next waits, and a spawn of Desk's own lines up behind it; the start's answer starts the next while a place is free, so a raised cap or a freed place fills every place it can, and raising the cap wakes the queue.
  A queued start refused because another start held the line (`spawn_busy`, nothing was started) waits on its thread for that start to let the line go, then goes back to its own place, first in line, and the queue asks it again (`after_start` and `desk_queued_answered` in `hide-core/src/runtime/desk/jobs.rs`); a spawn of Desk's own refused so waits first in the queue rather than read failed, and the agent that asked reads that it waits, first, as a spawn the queue admitted reads (the command's follow-up step replaces the answer before the asker reads it); one the full queue could not take reads `spawn_busy`.
  A start is a fact of the thread running it: Desk's store keeps it, and reading the store back reads it as waiting again, so a hided that ended under a start leaves no job starting for ever in front of the queue, and asking the same intent again converges on what the ledger already holds.
- hided gives the process its identity (`hided/src/desk_host.rs`): a capability bound to the process's pid and start time (`Binding::Desk` in `pane_auth.rs`), whose reference file is all the process's `HIDE_CAP_REF` names.
  The command boundary judges Desk's commands as a bot of the whole Hide (`Capability::reach`, then `ScopedRequest::access_need` and `hide_core::access::admit`), and the core again where a command names a caller (`Runtime::broad_authority`, shared with a bot's): Desk reads every project, agent, pane and mission, and is refused what is the operator's alone (`access_operator_only`) and what means an agent in a pane (`access_needs_agent`), with no mode of its own to set; the exceptions stay as they were, named in [delivery.md: Desk](../delivery.md#desk): it types into no pane, `agent sleep` stays refused, and `worktree remove` runs without `--force`.
  Desk has no checkout, so `hide links` and `hide session` read every Project's for it (`Scope::every_project`, decided from the caller's kind by `access::is_checkoutless_context`, never from a Project that is not found: a pane in a plain folder is still refused `workspace_unavailable`), and a Workspace or View command is still refused `desk_has_no_checkout` ([delivery.md: Desk](../delivery.md#desk)), except a file open.
- `hide file open <path>` from Desk puts the file in front of Desk's own desk (`hide-core/src/runtime/desk/opens.rs`, PRD desk-own-desk D-13, B35), as a press in Desk's room does, and moves `desk_view.opened`: a window showing Desk shows the desk for it, and a window on another screen moves nothing, so an open never pulls the operator away.
  The core takes the call through the Workspace action's own prepare and commit when the caller is Desk: the path must sit, by whole path segments, inside a checkout Hide shows on a connected machine, refused `desk_file_outside_project` otherwise and `desk_file_ambiguous_device` when projects on two machines hold it, and that checkout's host reads it (`ActionSource::read`, as an agent's `file_open`) before it opens, so a link out of the checkout or a missing file is refused before anything moves; hided skips the outside-file grant for Desk, since the desk shows no outside file and the path may be a device's.
  An open the desk has no room for (`MAX_VIEW_DISPLAYS` tabs, none of which may leave: each in front of its area or holding unsaved work, `make_view_room`) is refused `desk_open_refused`, and the agent reads that it did not open; a refused open is neither counted as an open nor remembered under its request id, so asking again after room is made opens it.
  The same request id, among the last 16, answers the open already made.
  `hide diff open` from Desk is refused `desk_diff_unsupported`: Desk's desk has no diff tab, and the core reads a diff only for the checkout in front (`changes_request`).

The worker is the process's one owner (engineering practice: resident processes).
Every ACP call, install and file check runs on it, never under `Mutex<Runtime>`; what it learns reaches the runtime as a report under a short lock.
The agent's own messages queue to the worker; past 4096 waiting, reply text is dropped and logged once, while requests and answers still queue, since the agent waits on them.
After each turn the tree is measured, and past 48 processes or 4 GiB it ends, which the room shows as stopped with `다시 시작`.
The process starts tied to hided, so it and everything it started end with hided however hided ends.
A program a tool opens as an application through LaunchServices on macOS is launchd's child and never in the tree: open-computer-use's app agent, which every client of the account shares on one socket under `TMPDIR`, is one, and it stays when Desk's agent ends, as it does when an agent in a pane ends.

A failed turn reads `답을 끝내지 못했어요` with the agent's own one-line reason when the agent answered with an error (a provider's refusal, a model it cannot reach), and with none when nothing the operator can act on is known (no answer, the stream's end); every failed turn is logged as `desk.turn_failed` with the error and the last line the adapter wrote to its error output.
An adapter that answers a failed turn as ended has its failure mark in its definition (`AdapterId::failed_turn_mark`), a `session_info_update` field and the value it holds then, read as data with no branch on the agent: codex-acp passes Codex's thread status on, which turns `systemError` only after a failed turn, then writes the model's error as reply text and answers `end_turn`, so a turn that met the mark ends failed whatever its stop reason, and the text after the mark is the failure's reason, not a reply (`TurnReader`, `hide-desk/src/session.rs`).
A turn the agent refuses for its sign-in (ACP's `auth_required`, as OpenCode answers for a provider with no key) is the open's refusal: the message, which the agent never took, goes back first among the queued messages with the agent's sign-in command beside it, as every message of a refused open does, and the process ends, so the next message starts one that reads the sign-in and the environment again.
So is any refusal from an agent that said, just before, that it is signed out (`hide_desk::session::sign_in_status`): codex-acp, finding a login it can no longer refresh, logs itself out, announces `_auth/status_update` with `authStatus.kind` `none` and answers the open with an internal error, and the worker reads that announcement on the connection's reader, ahead of the answer.
An agent that refused so reads signed out in the bar until a session of it opens again, whatever Hide AI's read says, since that read finds the login file and a login file can outlive its sign-in.

The process starts with the environment an agent the operator starts in a terminal has (`hide-desk/src/host.rs`): what it keeps of hided's own (the login variables, the shell, the language and the network route a Dock launch may set), then the account's environment as a new terminal gets it (`programs::account_environment`: every variable the login shell exports on macOS and Linux, read by the same ask that gives the account's `PATH` and kept until a startup file changes, so a start asks no shell of its own; the sign-in's environment on Windows), then Desk's own (`PATH` with `hide` first, its capability, each agent's settings), which win.
So a provider key or setting an agent's own configuration reads from the environment (OpenCode's `{env:BAI_API_KEY}`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) reaches Desk's agent as it reaches one in a pane, whether hided started from the Dock, which lacks what the startup files export, or from a terminal; the rest of hided's own environment stays out, since a terminal's carries that terminal's session.
No `HERDR_*` and no `HIDE_*` reaches it from either side but its capability, so no pane hook reads it as a pane's session and it is no pane, row or Memory session.
Its working folder is `~/.hide/state/desk/work`, which no checkout holds, so no project's settings or instructions load into it.

Each agent starts as it does in the operator's terminal, in its own default mode with the operator's own settings (PRD session-docs-and-assistant D-92, replacing D-53's ask modes):

- Claude's session starts with the adapter's own setting sources (the operator's user, project and local settings, `CLAUDE.md`, skills and hooks; a Hide hook does nothing in Desk, which runs in no pane) and no `session/set_mode`; its sign-in is the CLI's own.
- Codex runs with the account's own `CODEX_HOME` ([Agent profiles and accounts](0019-agent-profiles-and-accounts.md#agent-profiles-and-accounts)) in codex-acp's `workspace-write` preset (`INITIAL_AGENT_MODE`), the Codex CLI's own default: approvals `on-request` that the operator answers, and a sandbox that writes the workspace with no network.
  codex-acp 2.5.0 starts in one of its own presets, never in the `approval_policy` and `sandbox_mode` of the account's `config.toml`, and its default preset (`agent`) has a model answer what it would ask instead of the operator, so the CLI's default is the closest to the terminal ([INSTALL.md](../INSTALL.md#what-each-system-supports)).
  Its sandbox refuses the loopback hided listens on; Desk's instructions ask the agent to run every `hide` command with escalated permissions, and Codex asks Hide.
  Its command shell is not a login shell but still reads the shell's always-read startup file (`~/.zshenv`), so one that sets `PATH` outright, rather than adding to it, hides the `hide` Desk put first.
  The core refuses a Desk spawn that carries words for the agent's own CLI (`desk_spawn_args`) for every Desk agent, since those words can lift the new session's permissions.
  An older Hide's `~/.hide/state/desk/codex` folder is no longer read and is left in place.
- Pi runs through `pi-acp` with `PI_ACP_PI_COMMAND` naming the `pi` Hide found, with no extension of Hide's.
- OpenCode runs `opencode acp`, omp `omp --mode acp`, Antigravity `agy acp` and Grok `grok agent stdio`, each with the operator's own configuration.
  omp 18.7.0 asks over ACP (`session/request_permission`) only for `bash`, `delete`, `move` and an `edit` that deletes or moves; a write-tier tool (`write`, a plain `edit`, `ast_edit`) that the operator's omp settings ask for is asked with an Approve/Deny form that names no tool call, which Desk does not offer, so that call fails without a card ([INSTALL.md](../INSTALL.md#what-each-system-supports)); in omp's default mode those tools run without asking.
  Antigravity's command request carries the command as `CommandLine` and the folder as `Cwd`, which the request reader reads with the other agents' `command` and `cwd`.

So what an agent asks and what it runs without asking is its own: Hide reads only what it is asked.
How the core answers is the one choice under Desk's box (`DeskSettings::permission`, kept in `desk.json`, the same for every agent), read when the request arrives; `desk_settings_set` refuses a word the core does not know, and a stored word this build cannot read, from a later Hide, restores as `agent` with a `desk.permission_unknown` diagnostic, never as `allow_all`:

- `allow_all` (`다 허용`, the default): the core answers every request with the agent's `allow_once` option at once and draws no card.
- `agent` (`에이전트대로`): every request is a card of the agent's own options, in its order and with its names (`DeskOption`, `kind` one of `allow_once`, `allow_always`, `reject_once`, `reject_always`, or `other` for a kind a later agent adds), but a command line made only of `hide` commands, which the core answers `allow_once` itself.

A request that offers no `allow_once` option is a card under either choice, since Hide never picks an option the operator did not.
The Desk worker reads the request (`hide_desk::permission::read_request`), with the call the agent announced before it when the request carries only the call's id (Codex), into a card (`permission::card`) and, for a command, whether it is a `hide` line (`permission::hide_line`).
It keeps the agent's first 8 options (`MAX_OPTIONS`; agents offer two to six), each name cut at 200 bytes on a character (`MAX_OPTION_NAME_BYTES`), and leaves out an option whose id is longer than 256 bytes (`MAX_OPTION_ID_BYTES`), which cannot be cut and still be sent back; a card's options count against the conversation's bytes (`DeskItem::text_bytes`).
`hide_line` reads text only (`hide_shell::shell_line`): every command must be `hide` by its exact name (on Windows also `hide.exe`, in any case) or the `hide` Desk put first on the agent's `PATH`, a write may go only to `/dev/null` or a standard stream (`>&` followed by a word that is not digits alone or `-` writes a file, as `&>` and zsh's `>>&` always do, and the `!` of zsh's `>!`, `>&!` or `&>!` is a file named `!` to bash), and a redirection with no word after it (`ShellLine::missing_target`, which keeps the commands for the hooks), a command or process substitution, a heredoc that substitutes, a file read into a command, a function, a compound command or a variable set before a command makes the line the agent's to ask, so `hide ps | head` is a card; on Windows the line must read so as both a POSIX and a PowerShell line.
What the operator presses goes to the agent as that option (`desk_approval {id, option}`), and the card keeps the kind it chose (`chosen`) and the agent's name for it (`answer`), which the answered card shows for a kind Hide has no word for.
A card that offers no rejecting option has Hide's own `거절…`, sent as no option (`option: null`), which the core answers ACP's `cancelled` and records as refused; the core refuses `option: null` on a card that offers a rejecting option (`approval_option`).
`거절…` with a line refuses, cancels the turn, and at the turn's end sends the line to the agent framed as the operator's refusal (`hide_desk::refusal_message`), at most 2048 bytes; only a rejecting option takes a line.
A rejecting option pressed without a line (`이유 없이 거절`) leaves the turn to the agent, which says it was refused and goes on; an agent that ends its turn on it without a word after it instead (OpenCode 2.0.29, whose ACP reply carries no words, so a refusal without them interrupts its step and the turn ends cancelled, and Antigravity 1.5.17, whose turn ends as answered) has the refusal sent to it once that turn ends, framed the same way with the call's kind and no line, telling it not to try the same another way but to say in words that it did not run, and with no message shown as the operator's; the reply's length at the refusal is what tells a silent end from one that said so, the last plain refusal of a turn is the one told, and a turn the operator stopped or that failed, or one ending while a message of the operator's waits in line (which goes instead), sends nothing (`a_plain_refusal_the_agent_ended_its_turn_on_is_sent_to_it`, `a_plain_refusal_the_agent_answered_its_turn_after_without_a_word_is_sent_to_it`).
A new conversation, a restart, a stop or the process's end closes every waiting card as a refusal (D-52).
A card carries the folder its request acts in, the one the agent named or else Desk's working folder where the agent's shell starts (Claude's `Bash` names none), and for an edit the deepest folder holding every file it changes, none when a path cannot be named (`Card` in `hide-desk/src/permission.rs`).
`hide agent archive` from Desk is never refused `archive_confirmation_required`: the operator chose how Desk's requests run, so a Desk caller is the confirmation.

The instructions the agent gets are code-owned (`hide-desk/src/instructions.md`): its role, the `hide` commands it acts with, and to answer in the operator's language.
They go before the first ordinary message of a session that starts new, with the conversation so far when the operator switched agents (at most 64 KiB, the oldest left out), and the line of where work goes goes before the next ordinary message after that setting changed; a message that runs one of the agent's commands goes as written and defers both to the next ordinary message ([Desk's commands](#desks-commands), `hide_desk::Guide`).
The ACP session id is kept, so the next start loads it (`session/load`) when the adapter can; one that cannot be loaded starts new with the conversation carried, and says so.
A load replays the whole conversation as `session/update`s that all arrive before the load answers, while the worker reads its channel only after it sent the next prompt; so the worker numbers every message the agent sends as it arrives (`hide_desk::session::Arrivals`) and a turn owns only those numbered from its prompt on (`hide_desk::session::TurnReader`), and the replay, already in the conversation, joins no reply, whether `다시 시작` or hided's own restart started the process, for every agent that loads a session.
`다시 시작`, or a session that opens again, takes `Desk 에이전트가 멈췄어요 · 다시 시작` out of the conversation, so no live `다시 시작` stays under a process that runs.

A message the operator sends while a reply is being written, or while earlier ones wait, waits in Desk's store whole, its words, chips and files (`DeskQueuedMessage::attachments`), whose paths reach the agent before the words when it goes as they would have at once (`queued`, sent in the `desk` section's `conversation.queued` and in no item until it goes), at most 8, a ninth refused `desk_queued_full` and the section saying so (`queued_max`, `queued_full`); `desk_queued_remove` takes one out, and a message the agent never took goes back ahead of a full line, so the store reads at most nine. ■ (`desk_stop`) with messages waiting pauses the line (`queued_paused`, kept in the store): none goes at a turn's end until `desk_queued_send {id}` sends one while Desk rests or `desk_queued_resume` lets the line go again, and `desk_queued_clear` keeps what it took for 10 s for `desk_queued_restore`, which puts it back first, paused, its files counted as in use meanwhile (PRD desk-queue D-10).

#### Desk's commands

An agent lists its own commands over ACP v1 (`available_commands_update`, `{name, description, input.hint}`) after its session opens and again whenever they change, the operator's own skills among them, since Desk starts each agent with the operator's own settings (D-92); a command runs as the first text of a prompt, `/name args`, with no call of its own.
Every agent Desk speaks with sends that list as its session opens, with no prompt (measured on 2026-11-27 for Claude Code, Codex, Grok, OpenCode, Pi, omp and agy: one to three seconds once warm, 38 s for agy's cold start), so Hide reads each agent's list ahead of the operator (mission-106 command-lists): `/` lists it at once in Desk's composer and in a session's input for an agent Desk never talked to.
A thread of Desk's worker (`runtime/desk/lists.rs`) starts the agent's ACP process as Desk would, with no capability, opens a session in Desk's folder, takes the longest list it sends within a second of the first and ends the whole tree (`hide_desk::read_ahead::read`), one agent at a time and never under the lock; the read ends on its list, a refusal, 10 s after the session opened, 60 s from the start, Desk switched off or the worker's end, dropping the reader waits for its thread, and no model is asked, since nothing is prompted.
The read deletes the session it opened where the agent offers `session/delete` (Claude Code, Codex, OpenCode and Pi), so it does not stay among the agent's conversations to resume; omp, Grok and agy offer only `session/close`, which keeps it, so each read of theirs leaves one empty session in Desk's folder of their history.
The reader keeps no timer and looks at an agent at three moments only: a look at every agent (Desk turned on, hided starting, `다시 시작`), a change of the catalog (an agent switched on or off in Settings › Agents, the operator signing in to or out of one as Settings reads it), which reaches the reader alone rather than looking at Node and the adapters again, the reader keeping which agents are in place itself (a look sets them, an adapter installed adds one), the agent's adapter installed, and the operator opening the `/` menu on that agent, in Desk's box or a session's (`desk_commands_check`, once per opening, never per key), when the menu shows the list it has at once.
Each look replaces what the reader reads with the agents in place and switched on; each moment it digests what the agent's list depends on, its mark (`hide_desk::read_ahead::mark`): the adapter Hide pins, the agent's own program (its resolved file, size and change time, which an update replaces), each skill in the skills folder its definition names (`[account.paths] skills`, `hide_kit`'s `~/.agents/skills` for `"shared"`), read as file facts only, and whether the operator is signed out of it; it starts the agent only when the mark moved since the list it has, and not when a read of that same mark already failed, so a failure is tried again once the program, the skills or the sign-in moved, or once more at the operator's own press, `/` opened on that agent or `다시 시작` for every agent, as many times as they press; time alone never reads a list again, since a read can leave an empty session.
The agent whose Desk session is open is not read, since that session sends its list.
The mark and the time of each read are kept beside the lists in `agent-commands.json` (`read`, a key an older build reads past), so a restart reads nothing that did not move.
A read that brings no list says why, in the section's `unread` beside `lists`: `sign_in` (the agent refused the session for its sign-in), `no_list` (its session opened and sent none) or `failed` (it did not start or answer, the detail in the log as `desk.commands_unread`); the core adds what it knows itself: `reading` while a read is under way or waits for its turn, `not_installed` for an agent whose program is not on this machine, `agent_off` for one switched off in Settings › Agents, which Hide never starts to read, `failed` for an adapter that could not be prepared, and `desk_off` while Desk is off, since the reads run only while it is on.
`hide_desk::commands` is the one reader: it keeps a list's first 256 commands in the agent's order, leaves out a name past 64 bytes or one holding a space (it could not run cut), cuts a description at 200 bytes and a hint at 100 on a character with `…`, writes each as the operator types it (`/compact`, or a name with a sigil of its own as named, Codex's `$skill`), and logs `desk.commands_cut` with the count when a list that changed had any left out by the caps, which the operator cannot act on.
It leaves out the commands the agent's definition file names in `[desk] left_out` ([Agent definition files](0018-agent-definition-files.md#agent-definition-files)), those that would sign out the login Desk shares with the operator's terminal or move Desk's session or settings out of its hands: Codex's `/logout`; Claude Code's `/remote-control`, `/config` and `/auto-mode-setup`; omp's `/move`, `/wt`, `/ssh`, `/plugins`, `/force` and `/session delete`.
The worker reports each list (`Report::Commands`, with the read's mark when it was read ahead), and a read that brought none (`Report::Unread`), except for an agent whose Desk session is open, whose list is that session's; the core's general `AgentCommands` owner keeps each agent's last one (`Runtime::agent_commands`), replaced whole by the next, so a new conversation's first `/` has the list before its session opens, and saves the lists the agents sent to `agent-commands.json` off the lock (`AgentCommandsStore`, `hide_kit::layout::agent_commands`), read before the lock at the core's start, so an update or a restart lists them at once (letter-48626); the file keeps ACP's own entries, so reading it back is `hide_desk::commands::read_saved`, which applies the caps and the definition's left-outs of the build that reads it, skips an entry that is no command and leaves out with a diagnostic an agent this build does not know, and a file that cannot be read is no lists, with a diagnostic; every agent's list is the `desk_commands` section (`lists`, by agent), its own like `desk_mentions`, so a list of hundreds is not sent again with each change of the conversation; Desk's composer reads its selected agent's, and a session's input box its session's agent's ([Session threads](0026-session-threads.md#session-threads)).
